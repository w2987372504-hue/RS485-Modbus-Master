# RS485 + Modbus RTU 主机（温湿度采集）

基于 **STM32F103C8T6** 的 Modbus RTU **主机（Master）** 程序：通过 RS485 总线轮询温湿度变送器（从站），校验 CRC 后解析出温度、湿度，在 OLED 上实时显示。

---

> ## ⚠️ 重要说明：只实现了最基础的功能，非工业级
>
> **本工程属于学习 / 验证性质的代码，不是工业级实现，请勿直接用于实际生产场合。**
>
> 它缺少工业现场必备的超时重发、异常响应处理、通信错误上报、从站参数配置等机制。
> 最需要注意的是：**通信失败时程序不会给出任何提示，OLED 会继续显示上一次收到的旧值**，
> 从界面上看和正常数据一模一样。
>
> 逐条缺口列在文末的[「非工业级说明」](#非工业级说明)一节。

## 一、功能概览

| 项目 | 内容 |
|---|---|
| MCU | STM32F103C8T6 |
| 外设库 | STM32 标准外设库（StdPeriph Lib） |
| 物理层 | RS485 半双工，USART1 |
| 串口参数 | 9600 bps，8 数据位，1 停止位，无校验 |
| 协议 | Modbus RTU，**主机** |
| 功能码 | `0x04`（读输入寄存器） |
| 从站地址 | 固定 `0x01` |
| 轮询周期 | 2 秒 |
| 显示 | 0.96" OLED，温度 / 湿度各显示 1 位小数 |

## 二、硬件接线

| STM32 引脚 | 方向 | 用途 |
|---|---|---|
| PA9 | 输出 | USART1_TX → RS485 收发器 DI |
| PA10 | 输入 | USART1_RX ← RS485 收发器 RO |
| PB10 | 输出 | RS485 方向控制 |
| PB11 | 输出 | RS485 方向控制 |
| PB8 | 输出 | OLED SCL（软件 I2C） |
| PB9 | 输出 | OLED SDA（软件 I2C） |

半双工方向切换：

- `ModeO()` —— PB10 / PB11 置高，进入**发送**
- `ModeI()` —— PB10 / PB11 置低，进入**接收**

主循环平时停在接收态；到发送时刻切到发送态，发完等 `USART_FLAG_TC` 置位（最后一个字节真正移位出去），再切回接收态。

## 三、通信协议

### 主机请求（每 2 秒发一帧，8 字节）

```
 01   04   00 00   00 02   71 CB
 │    │    │       │       └────── CRC16（低字节在前）
 │    │    │       └────────────── 读 2 个寄存器
 │    │    └────────────────────── 起始地址 0x0000
 │    └─────────────────────────── 功能码 0x04 读输入寄存器
 └──────────────────────────────── 从站地址 0x01
```

### 从站应答（正常，9 字节）

```
 01   04   04   TT TT   HH HH   CRCL CRCH
 │    │    │    │       │       └──────── CRC16
 │    │    │    │       └──────────────── 湿度原始值
 │    │    │    └──────────────────────── 温度原始值
 │    │    └───────────────────────────── 数据字节数 = 4
 │    └────────────────────────────────── 功能码 0x04
 └─────────────────────────────────────── 从站地址 0x01
```

### 数值换算

| 量 | 换算规则 |
|---|---|
| 温度 | 原始值 `< 10000` → 温度 = 原始值 × 0.1 ℃<br>原始值 `≥ 10000` → 温度 = −(原始值 − 10000) × 0.1 ℃ |
| 湿度 | 湿度 = 原始值 × 0.1 %RH |

温度为负数时使用「10000 偏移」表示，例如原始值 `10253` 表示 −25.3 ℃。

## 四、代码结构

| 路径 | 作用 |
|---|---|
| `User/main.c` | 主循环：触发发送 → 收帧解码 → 刷新 OLED |
| `Hardware/Serial.c/.h` | USART1 初始化、收发函数、RS485 方向控制、接收中断 |
| `Hardware/Timer.c/.h` | TIM2 1 ms 时基：2 秒轮询节拍 + 5 ms 空闲判帧 |
| `Hardware/Modbus.c/.h` | Modbus RTU CRC16 计算 |
| `Hardware/jiema.c/.h` | 应答帧解析：地址校验 → CRC 校验 → 拆出温湿度 |
| `Hardware/OLED.c/.h` | OLED 驱动（软件 I2C） |
| `System/Delay.c/.h` | 延时函数 |
| `Library/` | STM32 标准外设库 |
| `Start/` | 启动文件、CMSIS 内核文件 |
| `Project.uvprojx` | Keil MDK 工程文件 |

### 接收与判帧流程

1. USART1 每收到一个字节进一次中断，存入 `Serial_RxData[]`，并把计数器 `Count` 清零、`TmFlag` 置 1。
2. TIM2 每 1 ms 中断一次，`Count` 在中断里自增。
3. 当 `Count` 累加到 5（即总线空闲约 5 ms 没有新字节）时，判定一帧结束，把本帧长度存入 `RxLen` 并置 `RxFlag`。
4. 主循环发现 `RxFlag` 后调用 `jiema()` 解析。Modbus RTU 规定帧间隔至少 3.5 个字符时间，9600 bps 下约 4 ms，这里用 5 ms 覆盖。

## 五、编译与下载

1. 用 **Keil MDK** 打开 `Project.uvprojx`
2. 器件选择 `STM32F103C8`
3. `Build`（F7）编译，`Download`（F8）下载

> 源码文件的编码是 **GBK（ANSI）**，在 Keil 中按默认的 `Encode in ANSI` 显示正常。
> 若用 VSCode 打开出现乱码，那是 VSCode 按 UTF-8 解码所致，文件本身没有问题。

## 非工业级说明

以下逐条列出本工程**没有做**的部分。列在这里不是自谦，而是明确边界，避免被当成可直接投产的代码。

### 协议层

1. **只实现了功能码 `0x04`**，没有 `0x03`（读保持寄存器）、`0x06` / `0x10`（写单个 / 多个寄存器）等主站功能。
2. **从站地址、寄存器地址、寄存器数量全部硬编码**（`0x01` / `0x0000` / `2`），没有任何配置接口。换一个从站、或想读别的寄存器，都必须改代码重新编译。
3. **完全没有异常响应处理**。从站地址错、寄存器不存在时，从站会返回异常帧（功能码 `0x84` + 异常码，共 5 字节）。本工程遇到这种帧只会在 CRC 校验环节静默返回，上层拿不到任何错误信息。
4. **解析函数只校验了从站地址和 CRC**，没有校验功能码（`arr[1]`）和数据字节数（`arr[2]`）。也就是说，只要地址和 CRC 对得上，帧结构是否符合预期并不会被检查。

### 可靠性

5. **没有超时重发机制**。请求发出去就不管了，从站不应答不会重试，也不统计丢包。
6. **没有通信错误上报**。解析失败时函数直接 `return`，主循环无从得知，OLED 继续显示上一次的旧值 —— 看起来和正常数据没有区别，这是本工程最需要警惕的一点。
7. **没有总线仲裁 / 冲突处理**，默认总线上只有自己一个主机。
8. **接收缓冲区固定 9 字节**，超出部分直接丢弃；帧长靠 5 ms 空闲判定，而没有使用硬件 IDLE 中断。
9. **没有看门狗**。程序跑飞或死循环时不会自动复位。

### 功能与架构

10. **只支持单从站**，没有多从站轮询调度。
11. **没有通信质量统计**（成功率、CRC 错误计数、超时次数等），无法评估现场总线状况。
12. **没有 RTOS**，是裸机 `while(1)` 结构。
13. **轮询周期固定 2 秒**，不可配置。
